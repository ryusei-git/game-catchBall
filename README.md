# 「キャッチ！」(仮) UX設計・市場評価予測レポート

作成日: 2026年7月27日
対象: Android向け シンプル落ち物キャッチ＋着せ替えゲーム（実装前フェーズ）

---

## 0. このレポートの結論（先に3行）

1. **アイコンだけでゲーム内容を伝えるのはほぼ不可能。** ただし「伝えるべき相手」は保護者（ストア）と子供（ホーム画面）で別なので、それぞれ役割を分けて設計すれば解決できる。
2. **同ジャンルの実在タイトルは 3.5〜4.0★ 帯に集中しており、点数を落としている主因はゲーム内容ではなく「広告の出し方」。** 逆に言えば広告設計だけで評価が決まる。
3. **最大の設計矛盾は「シンプルなキャラクター」×「着せ替え」。** シンプルな図形キャラは着せ替えの見栄えが出にくく、着せ替えを主要な継続動機に置くなら、キャラ設計を先に決める必要がある。

---

## 1. 前提整理：このゲームには「ユーザー」が2人いる

企画を評価する前に、誰の体験を設計するのかを分けておきます。ここが混ざると、後の判断がすべてぶれます。

| | 保護者（ゲート） | 子供（プレイヤー） |
|---|---|---|
| 何を見て判断するか | ストア掲載情報、レビュー、対象年齢、広告の有無 | ホーム画面のアイコン、最初の10秒の画面 |
| 判断基準 | 安全か／課金しないか／変な広告が出ないか | 楽しそうか／かわいいか／自分にできそうか |
| いつ関与するか | インストール時・課金時のみ | 毎回 |
| 失敗すると何が起きるか | そもそもインストールされない | 二度と開かれない |

**重要な非対称性**: インストールを決めるのは保護者、継続を決めるのは子供です。片方だけ最適化しても数字は伸びません。

## 2. 想定ユーザー体験（UX）

### 2-1. アイコンからゲーム内容を把握できるか

**結論から言うと、「ゲーム内容」の把握は無理です。狙うべきはそこではありません。**

アイコンはストア検索結果でもホーム画面でも、実サイズは概ね 48〜64px 程度です。この面積で伝えられる情報は、経験則として **1.5個** が上限です。「落ちてくる物を」「キャラを動かして」「キャッチして」「着せ替えもできる」——4要素は入りません。

さらに子供向けの場合、大人が学習済みのアイコン記号（ハンバーガーメニュー＝メニュー、虫めがね＝検索など）は、子供にはただの抽象的な図形として認識されるという指摘があります。抽象化した記号でルールを伝える方向は、子供相手には特に成立しにくいと考えるべきです。

#### 役割分担で解く

| 要素 | 担当する役割 | 設計方針 |
|---|---|---|
| **アイコン** | 「かわいい」「安全そう」「自分のアプリ」の識別 | キャラの顔をドアップで1体。背景は単色。文字は入れない |
| **1枚目スクショ** | ゲームルールの説明 | 落下する〇＋キャラ＋矢印で「動かしてキャッチ」を図解 |
| **2枚目スクショ** | 差別化ポイントの提示 | 着せ替え画面を大きく |
| **最初の10秒** | 実際の理解 | 遊びながら覚えさせる（後述） |

#### アイコン案の比較（実装前に3案作って実寸で見比べることを推奨）

| 案 | 内容 | ○ | × |
|---|---|---|---|
| A: 顔ドアップ | キャラの顔だけ | 小サイズで最も視認性が高い。子供が識別しやすい | ゲーム内容がゼロ伝わらない |
| B: キャッチの瞬間 | キャラ＋落ちてくる〇 | 内容が少し伝わる | 48pxでは〇が潰れて何か分からなくなりがち |
| C: 着せ替え済みキャラ | 王冠＋マント姿 | 「着せ替えできそう」が伝わる | 装飾でシルエットが崩れ、識別性が落ちる |

**推奨**: A をベースに、落下物を1個だけ大きく配置した A+ 案。実寸プレビュー（スマホのホーム画面に実際に置いて見る）で最終判断してください。

> 補足: Google Play Console には「ストアの掲載情報のテスト（Store Listing Experiments）」という無料のA/Bテスト機能があり、アイコン・スクリーンショット・説明文を実トラフィックで比較できます。将来ストア公開するなら、アイコンは最優先でテストすべき要素とされています。

#### 今回の配信形態での注意

現在の方針（HTMLファイル＋「ホーム画面に追加」）の場合、そもそもストアアイコンは存在せず、**ホーム画面アイコンだけ**になります。この場合アイコンの仕事は「他のアプリに埋もれず、子供が自力で見つけられること」の一点に絞られます。彩度の高い単色背景＋キャラ顔、が最適解です。

### 2-2. 初回60秒の体験シナリオ（設計目標）

子供の1タスクあたりの集中持続時間は8〜12分程度とされています。説明に時間を使う余裕はありません。

| 経過 | 画面 | 子供がすること | 設計上の要件 |
|---|---|---|---|
| 0-3秒 | ホーム | 「あそぶ」を押す | ボタンは画面の1/3を占める大きさ。文字＋アイコン併記 |
| 3-8秒 | ゲーム開始 | 何もしない（見ている） | **ここでチュートリアルを出さない。** 落下物が1個だけゆっくり落ちる |
| 8-15秒 | ゲーム | 指を置いて動かす | キャラの下に「指マーク」のアニメーションだけ表示。文字なし |
| 15-20秒 | ゲーム | 1個キャッチする | 派手な演出＋音。**必ず成功させる**（レベル1は失敗不可能な設計） |
| 20-50秒 | ゲーム | 数個キャッチ | 徐々に増やす。✕はまだ出さない |
| 50-60秒 | クリア画面 | コイン獲得を見る | 「きせかえ」ボタンを光らせる → 次の行動を提示 |

**原則**: テキストによる説明を一切書かず、行動で覚えさせる。文字が読めない子や、読むのが面倒な子を落とさないためです。これは Toca Boca などの子供向けアプリが徹底している方針でもあります。

### 2-3. つまずきポイントの予測（優先度順）

| # | リスク | 発生確率 | 影響 | 対策 |
|---|---|---|---|---|
| 1 | 親指がキャラを隠して見えない | **高** | 大 | キャラを画面最下部から 15〜20% 上に配置。操作エリアはその下 |
| 2 | 小1と小6で必要な難易度が違いすぎる | **高** | 大 | レベル選択を自由にする（クリア済みでなくても挑戦可）／失敗が続いたら自動で易化 |
| 3 | 着せ替えアイテムが少なく、すぐ飽きる | 高 | 中 | 初期リリースで最低15種。色替えは点数稼ぎにならないので数に含めない |
| 4 | コインが貯まらず着せ替えに到達しない | 中 | 大 | **初回クリア時に1着必ず無料で渡す**。所有体験を先に作る |
| 5 | 端末の画面サイズ差で難易度が変わる | 中 | 中 | 落下速度を秒速px固定ではなく「画面高さの何%／秒」で定義 |
| 6 | ✕アイテムに当たった時の演出が怖い | 低 | 中 | 破壊的・恐怖的な表現を避ける。しょんぼり顔＋軽い音まで |
| 7 | 誤って閉じてしまい、進捗が消える | 中 | 大 | localStorage 等で毎回自動保存。「つづきから」は不要（常に自動復帰） |

## 3. 市場調査：類似ゲームはどう評価されているか

### 3-1. ジャンルの現在地

* 落ち物キャッチゲームは1980年代アーケードにルーツを持つ、**完全にコモディティ化した定番ジャンル**です。App/Play ストアには専用のまとめカテゴリが存在するほど数があります。
* 市場全体としては、超シンプルな「ハイパーカジュアル」から、進行・メタ要素を足した「ハイブリッドカジュアル」へ移行が進んでいます。ハイパーカジュアルのダウンロード数は2021→2022年で15%減少したというデータもあります。
* 継続率のベンチマークとして、モバイルゲーム全体の7日目継続率は約20%であるのに対し、ハイパーカジュアルでは10%を下回ることが珍しくないとされています。
* ハイブリッドカジュアル収益の半分以上をパズルジャンルが占めており（2025年Q2）、アクション系のキャッチゲームは商業的には激戦かつ不利な位置にあります。

**示唆**: 商業的ヒットを狙うジャンルではありません。ただし今回の目的が「小学生でも遊べるものを作る」なら、この選択は妥当です。**評価軸を「DL数」ではなく「遊んだ子が楽しめたか」に置くべきです。**

### 3-2. 直接競合の実例

**スーパーもふもふキャッチ**（RedinC）— 今回の企画とほぼ同一のコンセプト

| 項目 | 内容 |
|---|---|
| 評価 | 3.6★（36件） / モバイル端末に限ると 4.0★（27件） |
| DL数 | 5,000+ |
| 対象年齢 | 3歳以上 |
| 操作 | 指1本で左右スライドのみ |
| 内容 | アイテムをカゴでキャッチ、NGアイテムを避ける、ライフ制 |
| メタ要素 | プレゼントBOXで「もふ部屋」のコレクションを増やす |
| 収益 | 広告表示あり |

企画の設計はほぼ同じです（スライド操作／good・badアイテム／ライフ制／収集メタ）。**着せ替えをコレクション対象にしている点だけが本作の差分**、という状況です。

**イーキャッチ** — 小学生が制作した爆弾キャッチゲーム。ドラッグのみの操作、ステージごとに背景とBGMが変化。「小学生が作った」という文脈自体が訴求になっている例です。

### 3-3. 低評価につながる典型パターン

同ジャンル・子供向けアプリのレビューを見ると、**ゲーム内容そのものへの不満より、広告と課金への不満が圧倒的に多い**という傾向が明確です。

| パターン | 具体例 | 本作での回避策 |
|---|---|---|
| **広告でプレイが止まる／進行不能になる** | 広告が出ると続きが遊べない、という趣旨の低評価 | 広告を入れないのが最善。入れるならクリア後のみ |
| **報酬のために他アプリのインストールを要求される** | 面倒だという不満 | オファーウォール系は使わない |
| **子供向けなのに課金しないと手に入らないアイテムが多すぎる** | 「お金のゲームみたい」という趣旨の指摘 | **着せ替えは全アイテムをプレイで入手可能にする** |
| **操作性が悪い（タップが反応しない・意図しない操作になる）** | 落ち物系全般に見られる | タッチ判定を広めに。ドラッグ開始位置をキャラ上に限定しない |
| **後半の難易度が急に上がる** | クリア不能で放置される | 難易度カーブを線形ではなく緩やかに。詰まったら救済 |

### 3-4. 高評価につながるパターン

* 広告が少ない／ないこと（レビューで明示的に褒められる要素）
* 幼児・低学年でも遊べること（保護者からの評価が高い）
* 見た目のかわいさ（子供向けでは機能より強い訴求）
* 追加コンテンツ（服・家具など）が継続的に増えること

## 4. 本作の評価予想

### 4-1. 想定スコア

| シナリオ | 条件 | 予想評価 |
|---|---|---|
| **A（推奨）** | 広告なし・課金なし・着せ替え15種以上 | **4.2〜4.6★**（ただしレビュー件数は少数） |
| B | クリア後のみ広告・着せ替えは全解放可能 | 3.8〜4.2★ |
| C | 中断広告あり・一部アイテム課金限定 | **3.0〜3.5★** ／「子供向けなのに」という趣旨の低評価が集中 |

※ 少数レビューの場合、スコアは数件の低評価で大きく振れます。総合4.0★以上は注目度・信頼の面で重要なしきい値とされているため、初期はレビュー件数が少ない前提で、地雷（広告・課金）を踏まない設計が最優先です。

### 4-2. 予想されるレビュー文（想定）

**ポジティブ側**
* 「子供でもすぐ遊べた」「操作が簡単で幼児でもできる」
* 「広告がなくて安心して渡せる」
* 「服を集めるのが楽しいらしく、自分から遊んでいる」

**ネガティブ側**
* 「すぐ飽きる」「ステージが単調」← **これが最も高い確率で来ます**
* 「着せ替えの種類が少ない」
* 「レベルが上がると難しすぎて子供がクリアできない」
* 「同じようなゲームが他にもある」

### 4-3. 強み・弱みの整理

| | 内容 |
|---|---|
| **強み** | 学習コストがほぼゼロ／着せ替えという明確な継続動機／広告・課金なしで出せば競合の弱点を直接突ける |
| **弱み** | ゲーム性の差別化がほぼない／シンプルなキャラは着せ替えの見栄えが出にくい／コンテンツ量が継続の生命線になる |
| **機会** | 同ジャンル上位でも広告体験が悪い。「広告なしのキャッチゲーム」というポジションは空いている |
| **脅威** | ジャンル自体が飽和・成熟。新規発見の導線がほぼない |

## 5. 実装前に決めておくべき論点（重要）

ここは実装に入る前に決着させたい項目です。後から変えると作り直しになります。

### 論点1: キャラクターのシンプルさ vs 着せ替えの魅力 ★最重要

「なるべくシンプルなキャラクター」と「着せ替えで継続させる」は正面から衝突します。丸と四角だけのキャラに帽子を乗せても、見た目の変化が小さく、集める動機になりません。

**選択肢:**
* **(a) キャラをシンプルに保ち、着せ替えは"おまけ"に格下げ** → 継続動機は「ステージクリア」に一本化する
* **(b) 着せ替えを主軸にし、キャラを少し情報量のあるデザインに** → シルエットが変わるアイテム（マント・大きな帽子・しっぽ）を用意する
* **(c) 体の色＋背景テーマも着せ替え対象にする** → 画面全体が変わるので、シンプルなキャラのままでも変化を大きく見せられる

**推奨は (c)。** シンプルさを維持したまま「変わった感」を最大化できます。

### 論点2: 難易度カーブの幅

小1（6歳）と小6（12歳）では反応速度も指の器用さも大きく違います。単一の難易度カーブでは両方を満たせません。

**推奨**: レベルを常に自由選択可能にし、「クリアしないと次に進めない」ロックをかけない。加えて、同じレベルで3回失敗したら落下速度を自動的に少し下げる（子供には見せない救済）。

### 論点3: 広告・課金の方針

**推奨: 両方なし。** 商業目的でないなら、これが評価・体験・実装コストのすべてで最適です。将来ストア配信して広告を入れる場合、子供のみを対象とするアプリは Google Play の「ファミリー向け自己認定広告SDKプログラム」に準拠したSDKからのみ広告を配信する必要があるなど、追加の制約が発生します。

### 論点4: セッション設計

1プレイの長さをどうするか。子供の集中持続時間（8〜12分）を踏まえると、**1ステージ 45〜60秒、3〜5ステージで一区切り** が現実的です。「あと1回」を誘発しつつ、区切りをつけやすい長さです。

## 6. 制度面の確認事項（将来ストア公開する場合）

HTMLとして手元で遊ぶ分には不要ですが、Google Play で配信する場合は以下が関係します。

* **ファミリーポリシーへの準拠** — 子供を対象ユーザーに含める場合は必須。
* **対象年齢の申告** — Play Console でターゲットユーザー年齢を宣言する必要があります。
* **広告SDKの制限** — 子供のみを対象とする場合、全広告が自己認定広告SDK経由である必要があります。
* **データセーフティ申告** — 何を収集するかの申告が必須。**何も収集しない設計にしておくのが圧倒的に楽です。**

## 7. 実装後すぐ行う検証（推奨）

作ったら、**必ず実際の小学生に触ってもらってください。** 大人のテストでは絶対に見つからない問題が出ます。

**最小構成のテスト（1人15分 × 5人で十分）**

| 手順 | 見るポイント |
|---|---|
| 1. アイコンだけ見せて「これ何のゲームだと思う？」 | アイコンの伝達力 |
| 2. 何も説明せず端末を渡す | 自力で「あそぶ」に到達できるか |
| 3. 黙って観察（絶対にヒントを出さない） | 何秒で操作方法に気づくか。60秒以内が合格ライン |
| 4. 5分プレイしてもらう | どのレベルで詰まるか。表情が変わる瞬間 |
| 5. 「もう1回やりたい？」と聞く | 継続意欲の直接確認 |
| 6. 着せ替え画面を見せる | 何のアイテムに手が伸びるか＝作るべきアイテムの方向性 |

**合格ライン**: 説明なしで60秒以内に操作を理解し、5分後に「もう1回」と言えば設計は成功です。
